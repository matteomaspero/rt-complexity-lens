## Goal

Produce an evidence-based, per-example metric audit of the in-app calculations against every available external reference (UCoMx v1.1, ApertureComplexity / PyComplexityMetric), expose any residual differences (no glossing over), and update the Validation Report UI + data to reflect the actual numbers — no hallucinated agreement claims.

## Scope of examples

All 25 DICOM-RT plans currently in `public/test-data/` (TG-119 ETH/TB 2A & 7F sets across CS/HN/MT/PR, plus EL/MO MLC tracking plans).

## Reference layers to compare against

1. **UCoMx v1.1 (MATLAB)** — already-shipped `testdata/reference_dataset_v1.1/.../dataset.xlsx`. Re-run `python/tests/cross_validate_ucomx.py` for every overlapping metric (not just core 4).
2. **ApertureComplexity / PyComplexityMetric** (Younge edge metric) — already wired via `python/tests/benchmark_pycomplexity.py`. Re-run on every plan and compare against our `EM` metric (same definition: perimeter/area, MU-weighted).
3. **TS ↔ Python parity** — re-run `python/tests/cross_validate.py` (existing) on all 25 plans, recording mean/max deltas per metric.
4. **Add if missing**: a tiny adapter to also compare our `PI` (Park MI / plan irregularity) and `MCS`/`LSV`/`AAV` numerics against `pylinac`'s `MLCAnalysis` complexity outputs where they overlap — only if `pylinac` ≥ 3.x exposes them in a stable API. If not feasible, document the gap explicitly instead of inventing one.

## Deliverable structure

### Data artifacts (under `python/tests/reference_data/`)

- `audit_ucomx_per_plan.json` — `{plan: {metric: {ts, ucomx, abs_delta, rel_delta, within_tol}}}` for all comparable metrics × 25 plans.
- `audit_pycomplexity_per_plan.json` — `{plan: {beam_id: {ours_EM, pycomplexity_CI, abs_delta}}}` plus plan-level MU-weighted aggregate.
- `audit_summary.json` — rolled-up mean/max/95th-percentile deltas per metric per reference, plus list of plans where any metric is outside tolerance.

### Scripts (new or extended)

- `python/tests/audit_all.py` — orchestrator: runs the three cross-validators in sequence, writes the three JSON artifacts and a Markdown summary `python/tests/reference_data/AUDIT_REPORT.md`.
- Extend `cross_validate_ucomx.py` to emit per-plan JSON (it currently only prints).
- Extend `benchmark_pycomplexity.py` to also compute our EM via the existing TS-exported reference data and write per-plan deltas (NOT recompute TS — read the JSON already generated by `src/test/export-metrics-json.test.ts`).

### Validation Report UI (`src/pages/ValidationReport.tsx` + `src/lib/validation-data.ts`)

- Replace the current "all green / 0.000000" `PER_METRIC_DELTAS` table with the real per-metric numbers from `audit_summary.json` (TS ↔ Python column kept, plus new "vs UCoMx" and "vs ApertureComplexity EM" columns where applicable).
- New section "Per-Plan Outliers" listing any (plan, metric, reference) tuple that exceeds the tolerance defined in `METRIC_TOLERANCES`, with the actual delta — empty if none, but driven by data, not hard-coded.
- Update `CROSS_VALIDATION_SUMMARY` `lastValidated` to today and add `ucomxComparedMetrics`, `pycomplexityComparedBeams` counts.
- Add a short "Methodology" paragraph naming exactly which UCoMx columns map to which TS metric (sourced from `UCOMX_TO_TS` dict) so the comparison is auditable.

### Docs

- `docs/ALGORITHMS.md` — append an "Audit results (YYYY-MM-DD)" subsection summarizing what matched, what didn't, and the rationale for any residual delta (e.g. MATLAB rounding, definition variant). No claim of agreement that isn't backed by the JSON artifacts.

## Honesty / anti-hallucination rules

- Every number rendered in the UI must be traceable to one of the three JSON artifacts checked into the repo.
- Metrics with no external reference are clearly labelled "TS↔Python parity only" — not implied to be UCoMx-validated.
- If a UCoMx column has no TS equivalent (e.g. `MUcGy`, `MCSv`), it's listed under "Not yet implemented" rather than silently dropped.
- If ApertureComplexity install fails in this sandbox, the audit runs the other two layers and the report explicitly states the third layer was skipped (with reason).

## Out of scope

- Implementing missing metrics (MCSv, Park MI_t/MI_s/MI_a) — flagged as gaps only.
- Refactoring the validation page layout beyond adding the new sections.

## Validation steps before finishing

1. `cd python && python tests/audit_all.py` runs cleanly and writes all three JSON artifacts.
2. Numbers in `validation-data.ts` byte-match the JSON summary (spot-check 3 metrics).
3. `npm run build` succeeds.
4. `/validation` route renders the new tables without runtime errors.
